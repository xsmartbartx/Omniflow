Why Constans

Built for the moment a step fails.

Most workflow tools are good at the happy path. Constans is designed around what happens next.

Safe by construction

One effect, once.

Retries and crashes do not repeat a charge, an email or a deploy. The key is recorded before the step acts, so "did that go through twice?" has an answer.

Honest failures

Know why it stopped.

Failures are classified. Only the ones you choose are retried; the rest stop, roll back in reverse order, and say why in plain words.

Small to operate

Nothing to babysit.

One container and one file. It does not scale across machines, and we say so up front. If you need a cluster, this is not the right tool yet.

How it works

Describe it. Check it. See what happened.

  1. Write or describe a workflow

    A short manifest, or a plain-language draft that a person must review. AI may propose; it never runs anything on its own.

  2. It is checked, then it runs

    Unknown steps, bad references and missing idempotency keys are errors with a line number, found before anything runs.

  3. Every run explains itself

    Attempts, retries and approvals land in a tamper-evident log. Any run can be read back in plain text.

approval-gated-refund.yaml
# a person must approve before the refund
steps:
  - id: validate
    type: capability
    uses: util-assert@^1
  - id: sign-off
    type: approval
    dependsOn: [validate]
    approvers: { roles: [approver, admin] }
    timeout: 4h
    onTimeout: deny
  - id: refund
    type: capability
    dependsOn: [sign-off]
    idempotencyKey: "refund-${{ inputs.orderId }}"

Capabilities

Everything a durable workflow needs. Nothing it doesn't.

Exactly-once effects

Idempotency keys are recorded before a step acts, so retries and restarts never repeat an effect.

Retry only what should be retried

Choose which failure classes retry. Contract and authorisation failures stop and explain.

Undo in order

Failed workflows roll back completed steps in reverse, with the rollback itself recorded.

Approvals that cost nothing while they wait

Four-eyes review for changes and for individual steps. A paused run holds no resources.

An audit trail nobody can quietly edit

Hash-chained events with a one-click integrity check and export.

One container

Security & governance

Authority is earned, not assumed.

  • Default-deny network. Steps reach only the hosts they declare.
  • Secrets stay secret. Leased per step, scrubbed from logs, never stored in plans.
  • Four-eyes by default. Whoever requests a change cannot approve it.
  • Tenant isolation in the data layer, tested.

Questions

Straight answers.

Can I import from other tools?

There are importers for crontab files and shell scripts. There is no importer for n8n, Zapier, Airflow or Temporal workflows.

What happens at my plan limit?

New runs are refused with a clear message until the next period or an upgrade. Nothing is billed beyond your plan, and dry runs always work.

Does the AI run my workflows?

No. AI drafts and proposes; every draft goes through the same checks and human approval as anything else.

Where does my data live?

In one SQLite file in the deployment you choose.

Is it open source?

No. Constans is proprietary software.

Does it scale across machines?

No. It is a single-node service by design. High availability means restarting quickly. If you need a cluster, this is not the right tool yet.
